Historial: 0.2.0 (`d13587d`, HU001); 0.3.0 (`92c03d9`, PR #3) agrega `POST /v1/sessions` y `POST /v1/sessions/refresh` (HU003); 0.4.0 (`2046411`, PR #6) saca el refresh token del cuerpo y lo fija en la cookie `HttpOnly` `__Secure-sportapp_refresh`, `/refresh` va sin cuerpo y ambas operaciones exigen un `Origin` permitido (`403 origin_not_allowed`); 0.5.0 (`bafa8a5`, PR #8) agrega `GET /v1/me/capabilities`; 0.6.0 (`5593d56`, PR #9) agrega las operaciones de planes y autorizaciones de entrenamiento (HU010); 0.7.0 (`ca4cb2c`, PR #11) agrega `POST /v1/sessions/revoke` (HU004); 0.8.0 (`24ef7db`, PR #12) agrega `GET /v1/training-history` y `GET /v1/athletes/{athlete_id}/training-history` (HU011). 0.9.0 (`eaca5d2`, PR #13) agrega `POST /v1/services` (HU015); 0.10.0 (`01c314a`, PR #14) agrega `POST /v1/events` (HU021). 0.11.0 (`c1f63ff`, PR #18) agrega `GET /v1/me/services`, `GET /v1/me/services/{service_id}` y `POST /v1/services/{service_id}/publish` (HU019); 0.12.0 (`bcdce86`, PR #19) agrega `GET /v1/services/availability` (HU020); 0.13.0 (`1ea49c8`, PR #21) agrega `GET /v1/me/profile`, `PUT /v1/me/demographic-profile` y `PUT /v1/me/physiological-profile` (HU005). De 0.6.0 a 0.13.0 no cambia ninguna operación ni esquema que ya consumía la web. `POST /v1/users` no cambia desde 0.2.0.

La web consume de 0.13.0 `POST /v1/users` (HU001), `POST /v1/sessions`, `POST /v1/sessions/refresh` y `GET /v1/me/capabilities` (HU003), y las operaciones de HU010: `POST /v1/me/training-authorizations`, `DELETE /v1/me/training-authorizations/{professional_id}`, `POST /v1/training-plans` y `GET /v1/training-plans/{plan_id}` (`bff-web/training.api.ts`), y las de HU011: `GET /v1/training-history` y `GET /v1/athletes/{athlete_id}/training-history` (`bff-web/training-history.api.ts`), la de HU021: `POST /v1/events` (`bff-web/events.api.ts`), la de HU020: `GET /v1/services/availability` (`bff-web/services-availability.api.ts`) y las tres de HU005: `GET /v1/me/profile`, `PUT /v1/me/demographic-profile` y `PUT /v1/me/physiological-profile` (`bff-web/profile.api.ts`). También consume la de HU004: `POST /v1/sessions/revoke` (`bff-web/sessions.api.ts`). `POST /v1/services` (HU015) y las operaciones de HU019 aún no tienen cliente.

`bff-web/*.contract.spec.ts` verifica que los modelos de transporte y los datos del simulador correspondan a esta copia.
